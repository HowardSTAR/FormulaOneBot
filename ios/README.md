# TurboTears iOS

Нативный клиент: SwiftUI, Swift 6 language mode, Observation,
async/await, URLSession. Минимальная версия iOS — 26.0; сборка проверена
в Xcode 27.2 со Swift 6.4.2. Внешних зависимостей нет.

Папка самостоятельна: Xcode-проект, исходники и тесты не зависят от файлов
родительского репозитория. Её можно перенести в `turbotears-ios`.
Отдельный Git-репозиторий и удалённый origin пока не создавались.

## Запуск

1. Открыть `TurboTears.xcodeproj` в Xcode.
2. Выбрать схему TurboTears и симулятор iPhone с iOS 26 или новее.
   Если runtime отсутствует, установить его в Xcode → Settings → Components.
3. Запустить локальный backend из корня Python-проекта:

   ```bash
   .venv/bin/python run_web.py
   ```

   Локальный API должен обслуживать `http://localhost:8000/api/v1/weekend?season=2026`.
   При другом порте изменить адрес в настройках приложения.
4. Нажать Run. В меню календаря выбрать сезон и ближайший/конкретный этап.

На симуляторе localhost указывает на Mac. На настоящем iPhone использовать
HTTPS-адрес сервера с новым маршрутом API. Приложение не развёртывает backend;
на публичном сервере маршрут появится только после отдельного деплоя.
Для запуска на устройстве выбрать свою Team и уникальный Bundle Identifier.
Текущий `org.turbotears.ios` — предварительный идентификатор проекта.

Настройки доступны через шестерёнку. Удалённый адрес должен использовать HTTPS;
локальный HTTP допускается для localhost/loopback. Глобального отключения ATS нет.
Первоначальный адрес предназначен для разработки, перед релизом его нужно заменить.

## Поведение

- Публичный запрос `/api/v1/weekend`: вход не нужен.
- Вкладки «Обзор / Уик-энд / Меню» на системном TabView.
- Главная: ближайший этап, следующая сессия и пять лидеров зачёта пилотов/команд.
- Выбор сезона и этапа, pull-to-refresh и повтор после ошибки.
- Результаты практик, квалификации, спринтов и гонки с сохранением season/round/session.
  Ответ другого этапа или другой практики не показывается как выбранная классификация.
- Статистика трассы из существующего `/api/circuit-profile`: составы, оценки,
  история, давления и источники. Профиль другого этапа не подменяет выбранный.
- Ссылка на существующий ICS-календарь выбранного этапа.
- Точная семантическая палитра веба из `front/src/assets/design-system.css`.
  Тему можно выбрать в «Меню»: системная, светлая или тёмная; выбор сохраняется.
- Успешный ответ сохраняется атомарно в системном каталоге Caches.
  Кеш разделён по серверу, сезону и этапу; система вправе удалить его.
- Сохранённые данные показываются сразу с явной отметкой и временем сохранения,
  пока запрашивается обновление. После ошибки они остаются на экране.
- `no_schedule` не стирает последнюю успешную копию. Время неизвестной сессии
  остаётся неизвестным; опубликованная календарная дата не превращается в момент старта.
- Неизвестные коды сессий не ломают декодирование. Они используют исходное имя.
- Отмена запроса и смена выбора не позволяют запоздалому ответу заменить новый экран.
- UI сейчас на русском; данные провайдера сохраняют исходный язык.

## Структура

- `TurboTears/App` — точка входа и сохранение адреса API.
- `TurboTears/Core` — модели контракта, сеть, кеш, наблюдаемое состояние экрана.
- `TurboTears/Features/Weekend` — SwiftUI-экран и настройки сервера.
- `Tests` — Swift Testing: контракт JSON, сеть/404, ключи запросов, офлайн-кеш.
- `Package.swift` — запуск тестов Core на Mac без симулятора; приложение
  собирается Xcode-проектом из тех же исходников.

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild \
  -project TurboTears.xcodeproj -scheme TurboTears -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath DerivedData CODE_SIGNING_ALLOWED=NO build
```

## Дизайн и границы проверки

Задача экрана — быстро увидеть этап и время сессий. Иерархию задают название
этапа и последовательность расписания, а не декоративные панели.
Используются системные List, NavigationStack, Menu, Form и toolbar; нативные
материалы навигации подхватываются системой. Контент не покрыт стеклом.
Семантические цвета, системные стили текста, отсутствие фиксированной высоты
строк и сгруппированные VoiceOver-подписи заложены в коде. Кастомных анимаций нет.

Основа — apple-design: accessibility › Vision, typography, layout,
liquid-glass › Review checklist. Это проверка исходников, не подтверждение
доступности: обе темы, крупнейший Dynamic Type, VoiceOver, Reduce Transparency
и разворот устройства ещё требуют проверки на симуляторе/устройстве.

Xcode собрал приложение для симулятора; девять тестов Core прошли.
Светлая главная и тёмный уик-энд проверены на запущенном iPhone 18 Pro / iOS 27.2
с изолированным fixture-сервером. Скриншоты — в `Preview/screenshots`.
Во время проверки исправлены контраст основной кнопки и вторичного текста.
Нажатия всех контролов, VoiceOver, максимальный Dynamic Type, импорт ICS и
сквозные сценарии на реальном источнике данных ещё не проверены.

Fixture-сервер запускается отдельно: `python3 Preview/server.py` из `ios/`.
Он слушает только `127.0.0.1:18765`; названия явно обозначены как тестовые.
Сервер не используется production-кодом, рабочая БД не затрагивается.
Для проверки можно временно указать `http://localhost:18765` в настройках.
В Debug-сборке переменная окружения `TURBOTEARS_PREVIEW_TAB=0|1|2` позволяет
выбрать стартовую вкладку для снимков. В Release этот механизм отсутствует.

До App Store ещё нужны иконка, локализация, юридические экраны, подпись и
проверки на устройстве. Карты трасс, флаги, портреты, полные страницы зачётов, календарь сезона,
авторизация, личные разделы, прогнозы, уведомления, виджеты и Live Activities
ещё не перенесены. Главная пока содержит публичные блоки обзора; это не полная
копия всех разделов веб-приложения.
