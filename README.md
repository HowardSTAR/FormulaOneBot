# TurboTears

Open-source motorsport statistics and race companion.

[TurboTears](https://t.me/turbotearsbot) — независимый неофициальный некоммерческий проект с Telegram-ботом и Web/Mini App. Он показывает расписания, результаты, сравнения и аналитику автоспорта.

Проект не является официальным продуктом и не связан с Formula One Group, FIA, командами, гонщиками или организаторами этапов.

## Возможности

- календарь этапов и расписание сессий;
- результаты практик, квалификаций, спринтов и гонок;
- зачёты пилотов и команд;
- сравнение статистики;
- избранное, уведомления, голосования и прогнозы;
- независимые игры «Тест реакции» и Reflex Grid;
- единый профиль сайта и Telegram.

## Статус проекта

TurboTears распространяется как бесплатный некоммерческий фан-проект. До получения отдельных разрешений в проекте не должны появляться подписки, реклама, платные уровни, спонсорская интеграция или продажа доступа к данным.

Гоночные данные агрегируются через независимые сторонние интеграции, включая OpenF1, FastF1 и Jolpica-совместимые API. MIT-лицензия FastF1 относится к коду библиотеки и сама по себе не лицензирует результаты, статистику или timing data.

## Правовая информация

В Web/Mini App доступны публичные маршруты:

- `/privacy` — политика конфиденциальности;
- `/terms` — условия использования;
- `/legal/ip` — уведомление об интеллектуальной собственности и takedown-процедура;
- `/about/data` — источники и ограничения данных;
- `/account/delete` — порядок удаления аккаунта и персональных данных.

Перед production-сборкой заполните фактические реквизиты оператора из `front/.env.example`, проверьте `LEGAL_COMPLIANCE.md` и зарегистрируйте URL собственной Privacy Policy через BotFather.

## Локальный запуск

Backend:

```bash
python -m venv .venv
pip install -r requirements.txt
python run_web.py
```

Фоновые задачи теперь запускаются отдельным процессом: `python -m app.worker`.
Перед production-запуском выполняется `python -m app.migrate`; Docker Compose
делает это отдельным шагом. Восстановление расчётов, проверяемые резервные копии
и перенос на ПК описаны в [docs/background-runtime.md](docs/background-runtime.md).

Frontend:

```bash
cd front
npm ci
npm run dev
```

Подробности находятся в `LOCAL_WEB_GUIDE.md`.

## Проверка перед обновлением

В активированной Python-среде с установленными зависимостями:

```text
python scripts/check_regression.py
```

Проверяются бот, API, права доступа, фронтенд, игры и production-сборка.
Используется временная тестовая БД; рабочая БД и `.env` не изменяются.
Детали оптимизаций и замеров — в [docs/code-optimization.md](docs/code-optimization.md).

## Дизайн: Apple Design Skill и WCAG 2.2 AA

Три новые композиции главной для телефона и десктопа доступны в локальной
галерее `/tests/home-glass-options.html` после запуска `npm run dev` из `front`.
Варианты, применение Liquid Glass и результаты проверки описаны в
[home-glass-options.md](docs/home-glass-options.md).

Интерфейс развивается по [Apple Design Skill](https://github.com/dickwu/apple-design-skill)
и с целевыми требованиями [WCAG 2.2 AA](https://www.w3.org/TR/WCAG22/).
TurboTears использует React, TypeScript и HTML/CSS. Рекомендации HIG
переводятся в доступные HTML/CSS-паттерны для сайта и Telegram Mini App.

Фразы в разделе **Use it** README скилла — примеры задач для агента.
Запрос определяет режим работы: ревью экрана, аудит доступности, улучшение
дизайна, проверка навигации, иконки или разрешений. Упоминания Flutter, Tauri
и React Native в этих примерах описывают возможные платформы; для TurboTears
в запросах нужно указывать React Web / Telegram Mini App.

### Как применять скилл

1. Прочитать `SKILL.md` и выбрать подходящие материалы через
   `references/hig-lookup.md`. Обычно нужны accessibility, layout, typography,
   color и дополнительные разделы для конкретного экрана.
2. Проверить существующий экран и пользовательский сценарий. Для замечаний
   указать проблему, её влияние, конкретное исправление и раздел HIG.
   Собственные дизайнерские решения явно отличать от требований Apple.
3. Для редизайна использовать **Design improvement mode**: сформулировать задачу
   экрана, палитру двух тем, роли шрифтов, компактную и широкую компоновки,
   один узнаваемый элемент TurboTears и необходимую анимацию.
4. Проверить, не получился ли очередной универсальный шаблон. Уточнить
   композицию и убрать элементы, которые не помогают пользоваться приложением.
5. Внести изменения в React-код, затем проверить обе темы, клавиатуру, фокус,
   контраст, увеличение текста, узкие экраны и состояния ошибок.

Локальные правила находятся в [front/AGENTS.md](front/AGENTS.md), общие токены —
в [design-system.css](front/src/assets/design-system.css). Краткое описание
дизайна и результатов проверки должно сопровождать каждый обновлённый экран.

### Что означает Apple style в этом проекте

Содержание получает приоритет, навигация остаётся знакомой, типографика задаёт
иерархию, а материалы и движение объясняют связи между элементами. Узнаваемость
TurboTears сохраняется через гоночные данные, схему трассы и сдержанный красный
акцент. Одни скругления и светлый фон не являются достаточным результатом.

Для Liquid Glass используется разделение контента и плавающих элементов
управления из [руководства скилла](https://github.com/dickwu/apple-design-skill/blob/main/references/hig/liquid-glass.md).
На главной стеклянные эффекты применены к плавающей панели управления,
боковой навигации на десктопе и нижней навигации на телефоне;
карточки расписания и зачётов сохраняют читаемые поверхности. В веб-интерфейсе
такое оформление является визуальной адаптацией, а не нативным материалом Apple.

### Что уже сделано и что ещё проверять

23 октября 2026 года `apple-design` установлен штатным `skill-installer` Codex
из `dickwu/apple-design-skill` в `$CODEX_HOME/skills/apple-design`.
Проверены `SKILL.md`, описание, таблица тем и 124 HIG-файла. Ранее материалы
читались как внешнее руководство без установки. Правило использования
установленного скилла закреплено в `front/AGENTS.md`.

Вся главная, включая раскрытые личные разделы, «Вне трассы», навигацию и
подвал, разобрана по пяти направлениям в
[home-design-review.md](docs/home-design-review.md). Применены общие токены
двух тем, нативные раскрытия, семантические списки, видимый фокус и сохраняемый
выбор темы. Изменения цвета навигации синхронны, без задержки значка профиля.

Главная и «Уик-энд» прошли проверки, описанные в
[home-design.md](docs/home-design.md) и [weekend-design.md](docs/weekend-design.md).
Решения по Liquid Glass, обзор главной по пяти направлениям скилла,
расчёт контраста и границы проверки описаны в
[home-liquid-glass.md](docs/home-liquid-glass.md). Используется CSS-адаптация:
непрозрачная основа, улучшение через backdrop-filter и возврат к сплошной
поверхности при уменьшении прозрачности или увеличении контраста.
Содержимое остальных экранов обновляется постепенно.

WCAG 2.2 AA — цель проверок. Автотесты и скриншоты не подтверждают полное
соответствие: дополнительно нужны ручной аудит и проверка реальным скринридером.
