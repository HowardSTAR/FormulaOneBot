# Аналитика предсказаний (admin preview)

Страница `/prediction-analytics` находится в меню «Аналитика» только у admin/superadmin.
Все `/api/admin/prediction-analytics` endpoints защищены той же проверкой роли и CSRF,
что административная панель. Гости и обычные пользователи не могут читать расчёты по URL.

## Работа

1. Выберите будущий этап и сессию, нажмите «Рассчитать прогноз».
2. Фоновый расчёт ограничен тремя минутами. Его можно открыть позднее в истории.
3. Сохраняются входные данные, время отсечения, версия модели, seed, вероятности и источники.
4. После старта новые прогнозы этой сессии запрещены. Завершённые снимки не переписываются.
5. Планировщик **бота** раз в 10 минут проверяет классификацию только сохранённых прогнозов.
   Проверка начинается через четыре часа после планового старта. Неполные данные не фиксируются.
   При отсутствии результата повторная проверка произойдёт позже. Фиксируется первая полная
   опубликованная классификация Jolpica; поздние апелляции/пересмотры автоматически не заменяют её.
   Сохраняются фактические позиции, время получения, MAE позиции и Brier победы/подиума.

Никаких Telegram/push-рассылок новый модуль не вызывает. После перезапуска он может
дописать факты для существующих прогнозов, но не создаёт прогнозов задним числом и не рассылает историю.
Зависший фоновый расчёт через 10 минут отмечается ошибкой; запустить новый можно вручную.

## Данные и ограничения

- Расписание — существующий адаптер FastF1; классификации — `https://api.jolpi.ca/ergast/f1/`.
- **Пять сезонов: текущий и четыре предыдущих**, все доступные завершённые гонки и квалификации.
  Для 2026 это 2022–2026. Последние шесть выступлений — только отдельный признак свежей формы,
  а не ограничение архива. Для запуска нужны хотя бы три классификации целевой дисциплины
  и состав текущего сезона. Покрытие, пропущенные источники и число наблюдений показаны на странице.
- Архив загружается по сезонам с пагинацией (части одной гонки объединяются), без скачивания
  каждой сессии отдельным запросом. Полные загрузки сохраняются в `prediction_history_cache`:
  текущий год на час, прошлые на 7 дней. Незавершённые загрузки не кэшируются. Даты фильтруются
  после чтения кэша; текущий уикенд исключён из истории и добавляется отдельно при доступности.
  При первом расчёте возможна долгая загрузка; уже полученные сезоны сохраняются даже при тайм-ауте.
- Если список участников предстоящего этапа ещё не опубликован, берётся последний состав текущего
  сезона с предупреждением. На старте нового сезона без подтверждённого состава расчёт недоступен.
- Для гонки — уже опубликованная квалификация, для квалификации — последняя доступная практика.
- Погода — Open-Meteo, прогноз осадков в час старта, температура и ветер; только в пределах горизонта.
  Осадки используются как упрощённая вероятность мокрых условий. Температура/ветер пока контекст.
  Нет координат/сервис недоступен — явная отметка и повышенная неопределённость, не ложный «сухой» прогноз.
- Новости — заголовки и ссылки BBC Sport RSS за последние 7 дней до отсечения. Совпадение фамилии
  пилота и английского ключевого слова crash/penalty/injury/damage/reliability/engine/gearbox/illness
  увеличивает масштаб случайного разброса на 5% за уникальную ссылку, максимум на 15%.
  Это **необученная эвристика неопределённости**, не подтверждение штрафа/поломки: текст может
  описывать отрицание или старое событие. Средний рейтинг и штрафы не меняются. Признак показан
  в объяснении пилота. При недоступности RSS множитель равен 1. Автоматический разбор
  подтверждённых штрафов/состава и обучение на новостных признаках не реализованы.

## Математика v2

Нормализованная позиция `1-(position-1)/(N-1)`. Взвешенное среднее сглаживается двумя
нейтральными наблюдениями. Вес истории: `2^(-дней/540)`. При прогнозе 2026+ данные до 2026
получают дополнительный множитель 0.4; это явная эвристика границы регламента, не обученная поправка.
Личные результаты в другой команде получают множитель 0.55, сравнение с напарником переносится
без этой поправки. Идентичность команды сопоставляется по ID или имени; переименования без
совпадения ID не объединяются автоматически. Сходы исключены из оценки темпа, но входят в риск схода.

Базовые веса гонки: долгосрочная форма 20%, свежая форма 22%, команда 20%, квалификационный
темп 12%, трасса 10%, напарник 10%, старт–финиш 6%. Для квалификации: 24/22/18/16/10/10/0%.
Отдельный признак квалификационного темпа коррелирует с общей формой; веса не означают
независимых причин и требуют последующей калибровки. Признак отыгрыша позиций исключает
сходы и неизвестный старт/старт из пит-лейна; это не число обгонов.

Квалификация текущего этапа смешивается с рейтингом гонки с весом 0.30;
практика для квалификации — 0.12. Квалификация не равна решётке после штрафов.
У каждой оценки показаны исходная величина, вес, вклад относительно нейтрального рейтинга,
число наблюдений и сумма весов (не статистический ESS). Отсутствующий фактор остаётся нейтральным.
Отдельно показаны последние 12 выступлений выбранного пилота.

12 000 Monte Carlo симуляций: Gumbel-возмущения рейтинга, отдельные сходы с Beta(1,9)
сглаженной взвешенной частотой: 60% риск пилота + 40% риск текущей команды.
Масштаб шума .15 сухо / .24 мокро / .20 неизвестно; дополнительно меняется в пределах
0.9–1.25 по стабильности последних 20 финишей (при малой выборке 1.25) и новостному признаку.
Для мокрых условий риск схода умножается на 1.3. Это **эвристические параметры**, не обученные коэффициенты.
Вероятности не откалиброваны; это исследовательский baseline, не доказанная точность прогноза.

Сценарии — непересекающиеся группы победителя по исходному рейтингу: первые 2, следующие 4,
остальные. Проценты относятся к группе, а показанная пятёрка — лишь пример симуляции этой группы.
Диапазон позиций — центральные 80% симуляций. Топ-10 в квалификации не обещает попадание в Q3.
MAE/Brier одного этапа не подтверждают калибровку; для этого нужна независимая серия прогнозов.
Снимки v1 сохраняются и отображаются без изменения; увеличение глубины не переписывает их.
Обучение коэффициентов, исторический walk-forward backtest, телеметрия шин/топлива,
эффекты обновлений машины и историческая форма именно в дождь пока не реализованы.

## Развёртывание и проверки

Новых Python-зависимостей/секретов нет. При запуске создаётся таблица `prediction_analytics`
в общей БД; после обновления кода перезапустить web **и bot**, собрать frontend.
Бот и web должны использовать одну БД. Боту нужен доступ к Jolpica, web — также к Open-Meteo/BBC.
При коммерческом использовании проверить условия выбранных провайдеров, в частности Open-Meteo.

`python -m pytest tests/test_prediction_analytics.py tests/test_prediction_history.py -q`

`npm --prefix front run build:front`
