# Первый этап iOS: контракт «Уик-энд»

Общий FastAPI обслуживает веб, Telegram и будущий SwiftUI-клиент.
Новый публичный маршрут `GET /api/v1/weekend` не требует аккаунта и не меняет
существующие `/api/next-race`, `/api/weekend-schedule` и `/api/race-details`.
Результаты сессий и авторизация — следующие отдельные этапы; этот контракт
охватывает выбор этапа, его описание и расписание.

## Запросы

```http
GET /api/v1/weekend?season=2026
GET /api/v1/weekend?season=2026&round=1
```

`season` обязателен (1950–2100). `round` необязателен (1–100).
Без `round` применяется существующее правило ближайшей гонки, общее с вебом
и ботом: первый подходящий этап с учётом шестичасового окна после старта гонки.
Это выбор по расписанию, а не по фактическому окончанию гонки.
С `round` возвращается указанный этап, в том числе архивный или отменённый.

## Успешный ответ

Пример формы ответа, не актуальное расписание:

```json
{
  "status": "ok",
  "season": 2026,
  "event": {
    "id": "2026:1",
    "round": 1,
    "name": "Australian Grand Prix",
    "country": "Australia",
    "location": "Melbourne",
    "date": "2026-03-08",
    "starts_at": "2026-03-08T04:00:00Z",
    "is_cancelled": false
  },
  "sessions": [
    {"code": "race", "source_name": "Race", "starts_at": "2026-03-08T04:00:00Z"}
  ],
  "schedule_status": "available"
}
```

- `event.id` — стабильный ключ `season:round`. Номер этапа уникален внутри сезона.
- `starts_at` — ISO 8601/RFC 3339 в UTC, либо `null`. Нельзя подставлять полночь
  при неизвестном времени. Известная дата без времени остаётся в `event.date`.
- `date` — календарная дата `YYYY-MM-DD`, либо `null`; не момент времени.
- `country` и `location` могут быть `null`. Все описанные ключи присутствуют.
- Подписи сессий и форматирование дат выполняет клиент в своём языке и часовом поясе.
- `source_name` — исходное имя провайдера, полезное для неизвестной сессии;
  это не идентификатор. Код: `practice_1`, `practice_2`, `practice_3`,
  `qualifying`, `sprint`, `sprint_qualifying`, `race`, `unknown`.
- Неизвестная сессия сохраняется с кодом `unknown`. Порядок сессий соответствует
  источнику; клиент может сортировать известные времена. Код не является
  уникальным ID строки: неизвестных сессий может быть несколько.

## Состояния экрана

| status | event | schedule_status | Значение |
|---|---|---|---|
| `ok` | объект | `available` | Источник вернул сессии |
| `ok` | объект | `unavailable` | Расписание не получено или ещё не опубликовано |
| `ok` | объект с `is_cancelled: true` | `cancelled` | Этап отменён, sessions пуст |
| `no_schedule` | null | `not_applicable` | Сезонное расписание не получено |
| `season_finished` | null | `not_applicable` | По общему правилу нет следующего этапа |

При двух последних состояниях `sessions` — пустой массив.
Существующие загрузчики источников возвращают пустые данные и при недоступности
провайдера. Поэтому `no_schedule` и `unavailable` не доказывают отсутствие
расписания: интерфейс должен предлагать повторить загрузку. `available` также
не означает, что все времена опубликованы, и не подтверждает свежесть данных.

Ошибки:

- `404`: расписание сезона есть, но запрошенного этапа нет;
  `{"detail":{"code":"weekend_not_found","message":"Этап не найден"}}`.
- `422`: неверные параметры, общий безопасный формат API:
  `{"detail":[{"loc":["query","season"],"type":"missing","msg":"..."}]}`.
- При сетевой ошибке или `5xx` клиент показывает повтор загрузки, сохраняя
  последние успешные данные с отметкой о сохранённой копии.

## OpenAPI и совместимость

Машиночитаемая схема доступна у запущенного FastAPI на `/openapi.json`.
Операция называется `getWeekend`, модели — `WeekendResponse`, `WeekendEvent`,
`WeekendSession`. OpenAPI генерируется из Pydantic-моделей, отдельную ручную
JSON-схему не поддерживаем. Сервер может ограничивать доступ к документации
на уровне прокси; для генерации клиента достаточно локального запуска.

Внутри v1 сохраняем смысл полей, типы и текущие значения состояний. Новые
необязательные поля допустимы; клиент игнорирует незнакомые JSON-ключи.
Несовместимые изменения требуют v2. При генерации Swift-моделей проверяем
обработку nullable-полей, дат и неизвестных значений enum.

## Проверка

```bash
.venv/bin/python -m pytest tests/test_weekend_contract.py tests/test_api.py -q
```

Проверки работают без внешних запросов и с изолированной БД: анонимный доступ,
сериализация UTC, неизвестные сессии, общий выбор ближайшего этапа, отмена,
неполные данные, 404/422, OpenAPI и прежний формат веб-расписания.

Следующий шаг: SwiftUI-экран, который получает этот ответ через URLSession,
показывает этап и расписание, поддерживает загрузку, повтор и локальный кеш.
