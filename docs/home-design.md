# Главная TurboTears · новый дизайн

Ветка: `feature/new_design`. Главная помогает за несколько секунд понять,
какой этап следующий, когда начнутся сессии и кто лидирует в чемпионате.
Её узнаваемый элемент — схема ближайшей трассы. Декоративные эффекты уступают
место данным, а красный акцент обозначает действия и выделение.

## Что дал apple-design-skill

[Репозиторий](https://github.com/dickwu/apple-design-skill) содержит инструкции
для анализа дизайна и подборку Apple Human Interface Guidelines. Это полезный
источник правил для последовательного улучшения экранов, а не библиотека
готовых React-компонентов. Для веб-приложения применены общие принципы HIG;
нативные меню macOS, SwiftUI и SF Symbols не имитируются.

Прочитаны SKILL.md, cross-platform.md и материалы об accessibility, layout,
typography, color, iOS, macOS, buttons, tab bars, sidebars и dark mode.
Ключевые решения опираются на:

- [Layout / Visual hierarchy](https://developer.apple.com/design/human-interface-guidelines/layout):
  сначала ближайший этап, затем расписание и зачёт; второстепенные разделы
  раскрываются по запросу.
- [Accessibility / Vision и Mobility](https://developer.apple.com/design/human-interface-guidelines/accessibility):
  контраст, зоны нажатия, текстовое обозначение следующей сессии, доступ
  с клавиатуры и увеличение текста.
- [Typography / Supporting Dynamic Type](https://developer.apple.com/design/human-interface-guidelines/typography):
  размеры в rem, перенос строк и гибкая высота строк вместо обрезания.
- [Color / Inclusive color](https://developer.apple.com/design/human-interface-guidelines/color):
  цвет дополняет текст и положение элемента, не заменяя их.
- [Buttons / Style](https://developer.apple.com/design/human-interface-guidelines/buttons):
  одно заметное действие «Открыть уик-энд», остальные ссылки спокойнее.
- [Dark Mode / Best practices](https://developer.apple.com/design/human-interface-guidelines/dark-mode):
  исходная системная тема и сохраняемый ручной выбор по пожеланию пользователя.

## Компоновка

```text
Десктоп                         Телефон
Меню | Обзор                    Бренд · Аккаунт
     | Этап       Расписание    Обзор · Сезон
     | Мой прогноз              Этап · схема трассы
     | Пилоты     Команды       Мой прогноз
     | Основные разделы         Расписание
     | Вне трассы ▸             Пилоты · Команды
                                Основные разделы
                                Нижняя навигация
```

Одна разметка на всех размерах. Ниже 1200 px расписание переходит под этап,
ниже 600 px зачёты выстраиваются вертикально. На главной меню и нижняя
навигация используют общий порог 900 px: на планшете не теряется доступ
к разделам. Игры, история, сообщество и личные настройки остаются доступны.

Удалены отдельные мобильная и десктопная версии главной, их неиспользуемые
стили, запрос всего календаря ради числа этапов и повторы расписания и
действия прогноза в напоминании над главным блоком. Прогноз и его срочный
статус остаются в персональной полосе; игровые напоминания сохранены.
Плановый старт больше не выдаётся за подтверждённый LIVE.

## Цвета и типографика

Общие токены вынесены в `front/src/assets/design-system.css`.
Плавающее управление главной обновлено с Liquid Glass; материал, варианты
доступности и результаты проверки описаны в [home-liquid-glass.md](home-liquid-glass.md).
Светлая тема: фон `#f5f5f7`, поверхность `#ffffff`, текст `#202126`,
вторичный текст `#64666e`, акцент `#b92b25`.
Тёмная: фон `#141518`, поверхность `#202125`, текст `#f2f2f4`,
вторичный текст `#b0b1ba`, акцент `#ff9b92`.

Контраст вторичного текста на карточке — 5.73:1 в светлой теме и 7.54:1
в тёмной. Белый текст основной кнопки на `#b92b25` — 6.11:1.
Акцент на выделенной строке расписания — 5.39:1 / 7.11:1.
Расчёт по относительной яркости sRGB из WCAG 2.x.

Системный шрифт с Inter как запасным. Заголовок страницы — 2–2.5 rem,
название этапа — 1.875–2.75 rem (в компактном мобильном акценте — 1.375 rem), строки данных — 0.875–1 rem,
второстепенные подписи — 0.75–0.8125 rem. Числа используют tabular-nums.
Новые ссылки и кнопки имеют зоны нажатия от 44 px. Навигация сохраняет
видимые подписи; графические значки не заменяют названия.

## WCAG

На 22 октября 2026 года [WCAG 3.0](https://www.w3.org/TR/wcag-3.0/)
остаётся Working Draft, а [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
имеет статус Recommendation. Основа проверок — WCAG 2.2 AA.
Обновление не является заявлением о полной совместимости со стандартом.

Предусмотрены ссылка обхода меню, семантические списки, иерархия заголовков,
видимый фокус, состояния ошибок и повтор загрузки, reduced motion,
контрастные режимы и непрозрачные поверхности. Таймер не объявляется
скринридером при каждом обновлении. Для полной оценки ещё нужны проверка
реальным скринридером и аудит остальных экранов и пользовательских сценариев.

## Предпросмотр и проверка

После запуска `npm run dev` в `front/`:

- `/tests/home-design-preview.html?theme=light` — светлая тема при первом открытии;
- `/tests/home-design-preview.html` — системная тема;
- `?theme=light&auth=member` — личная полоса вошедшего пользователя;
- `?theme=light&state=error` — ошибки API;
- `?theme=light&state=empty` — пустое расписание и зачёты;
- `?theme=light&state=cancelled` — отмена;
- `?theme=light&state=finished` — завершённый сезон;
- `?theme=light&scale=2` — увеличение текста до 200%.

Это только Vite-демонстрация с вымышленными данными, без обращения к backend.
Сохранённый выбор темы имеет приоритет над параметром theme; тему можно менять
настоящей кнопкой рядом с аккаунтом. Для нового экрана добавьте `page=weekend`.
Используется настоящее дерево маршрутов и компоненты приложения.
Файл не является entry point production-сборки; записи через API запрещены
внутри демонстрации. Обычный `/` использует настоящий API без подмены данных.

Автоматические проверки: `npm test`, `npm run lint`, `npx tsc -b`,
`npm run build:front`. Для выбора сессии проверяются границы времени,
невалидные даты, отмена и конец сезона. Визуальная проверка охватывает
320, 390, 820 и 1440 px, обе темы, раскрытие меню и увеличение текста.
Данные реального backend и production-развёртывание в эту проверку не входят.
