# Уведомления сайта

История доступна в `/notifications` после входа через email или Telegram. С первого открытия раздела аккаунт получает новые события. Старая история не импортируется из Telegram. Итоги сессий сохраняются текстом со ссылкой на полный протокол; результаты избранного выделяются отдельно.

## Настройка push

Установите зависимости из requirements.txt. Один раз создайте VAPID-ключи через `vapid --gen` (пакет py-vapid входит в зависимости pywebpush). Храните приватный ключ вне репозитория. В окружении web и bot настройте одинаковые:

- `WEB_PUSH_PRIVATE_KEY`: путь к PEM-файлу приватного ключа, доступному процессу bot.
- `WEB_PUSH_PUBLIC_KEY`: открытый ключ P-256 в формате uncompressed base64url (applicationServerKey, не PEM).
- `WEB_PUSH_SUBJECT`: контакт администратора, например `mailto:admin@example.com`.

Не генерируйте ключи при каждом запуске: это сломает существующие подписки. API и bot должны использовать один DATABASE_PATH. Доставкой занимается планировщик bot. Самостоятельный запуск только web не отправляет события.

Сайт должен работать по HTTPS; localhost подходит для разработки. `/notifications-sw.js`, manifest и иконки должны отдаваться как статические файлы, без подмены на index.html. Worker не кэширует API или персональные данные. Разрешение запрашивается только после нажатия «Включить push». На iPhone требуется установленное на главный экран веб-приложение и поддерживаемая версия iOS.

Адреса подписки ограничены push-сервисами Chrome, Firefox, Apple и Windows; частные адреса не принимаются. Подписка привязана к аккаунту. На общем устройстве отключайте push перед передачей устройства другому человеку.

## Защита от повторов

История уникальна по аккаунту и ключу события. Очередь уникальна по уведомлению и устройству, использует атомарную аренду, максимум 4 попытки и срок актуальности 1 час. При перезапуске старые задания push пропускаются; история сохраняется. HTTP 404/410 удаляет неработающую подписку. При аварии между приёмом push провайдером и сохранением квитанции возможна повторная доставка; одинаковый tag заменяет уведомление на устройстве.

## Проверка

`python -m pytest tests/test_web_notifications.py -q -o addopts=''`

`cd front` → `node --test tests/*.test.ts`, `npm run lint`, `npm run build`.

Реальную доставку проверяйте отдельным тестовым аккаунтом после настройки ключей. Автоматические тесты используют временную SQLite и подменённый push-сервис; не отправляют сообщения пользователям.
