# Регламент расчёта прогнозов F1Hub

Этот файл является технической спецификацией матрицы, которую использует
`app/services/prediction_service.py`.

## Матрица сезона 2026

- спринт-поул: 3 балла за точное совпадение;
- победитель спринта: 3 балла за точное совпадение;
- поул основной квалификации: 3 балла за точное совпадение;
- победитель гонки: 8 баллов точно, 3/2/1 при отклонении на 1/2/3 позиции;
- позиции 2–5: 5 баллов точно, 3/2/1 при отклонении на 1/2/3 позиции;
- лучший круг: 2 балла за точное совпадение;
- первый сход: 2 балла за точное совпадение;
- выезд физической машины безопасности: 2 балла за точный ответ.

Максимум обычного этапа — 37 баллов, спринт-этапа — 43 балла. Если внешний
источник не подтверждает необязательную категорию, она исключается и из
начисления, и из `max_points`; случайный ответ вместо официального факта не
подставляется.

## Официальные факты

Автоматический расчёт использует post-session классификации FastF1, а не live
позиции OpenF1. Позиции с DNS/DSQ/неклассифицированным результатом не попадают
в официальный топ-5.

Для «первого схода»:

- `Finished`, `Lapped`, `+1 Lap`, `+N Laps` считаются финишем;
- DNS, DSQ, excluded, withdrawn и общий NC не считаются сходом;
- среди подтверждённых DNF выбирается минимальное число завершённых кругов;
- при равенстве кругов нужен уникальный временной факт, иначе категория
  считается недоступной и не даёт баллов никому.

Safety Car нельзя надёжно вывести из одной таблицы итоговой классификации.
Superadmin может подтвердить этот факт при перерасчёте.

## Атомарность и история

Официальные ответы этапа, очки всех пользователей и запись
`prediction_score_runs` сохраняются одной SQLite-транзакцией. Ошибка любого
пользователя откатывает весь расчёт. Общий балл не хранится второй копией:
лидерборд суммирует актуальные `race_predictions.points`, поэтому повторный
расчёт заменяет баллы этапа и не удваивает сезонный результат.

Каждый успешный запуск получает монотонную `calculation_revision` и SHA-256
нормализованного набора официальных фактов.

## Перерасчёт после штрафов FIA

Требуются права `superadmin`, активная web-сессия и CSRF-заголовок:

```http
POST /api/admin/predictions/recalculate
Content-Type: application/json
X-CSRF-Token: <session-csrf>

{
  "season": 2026,
  "round": 12,
  "race_positions": {
    "NOR": 1,
    "PIA": 2,
    "LEC": 3,
    "HAM": 4,
    "RUS": 5,
    "VER": 20
  },
  "pole_driver": "NOR",
  "sprint_pole_driver": "NOR",
  "sprint_winner_driver": "PIA",
  "safety_car": true,
  "first_retirement_driver": "NOR",
  "fastest_lap_driver": "LEC"
}
```

Все override-поля необязательны. Если официальный протокол был изменён после
гонки, `race_positions` следует передать полностью: отсутствие пилота в этом
объекте означает, что он не классифицирован. Так перерасчёт не зависит от
устаревшего локального кэша FastF1. Переданные факты входят в SHA-256 ревизии и
историю аудита.

Спринт-этап автоматически не фиксируется, пока одновременно не доступны
протоколы спринт-квалификации и спринта. История запусков:

```http
GET /api/admin/predictions/score-runs?season=2026&round=12
```

## Порядок лидерборда

Сезонный зачёт сортируется по:

1. сумме баллов;
2. числу побед на этапах;
3. лучшему результату этапа;
4. постоянному `users.id` как стабильному последнему tie-breaker.

Для топа отдельного этапа после баллов используется время отправки прогноза,
затем `users.id`.
