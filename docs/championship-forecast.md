# Прогноз на чемпионство

Дополнительные вопросы появляются только для участников, которые могут оформить
титул к концу текущего этапа. Один кандидат подставляется автоматически; при
нескольких кандидатах участник выбирает пилота или команду. Ответ «Да» или «Нет»
обязателен для каждого доступного вопроса. Эти вопросы пока не меняют баллы
существующего рейтинга.

Список кандидатов относится к титулу на текущем этапе, а не ко всем участникам,
сохраняющим шанс на чемпионство к концу сезона. Для каждого кандидата проверяются
все соперники. В условиях могут одновременно фигурировать второй, третий и
следующие участники зачёта; расчёт не ограничивается ближайшим преследователем.

## Расчёт

Для каждого результата кандидата проверяются все соперники. Если `C` — очки
кандидата перед этапом, `x` — его очки на этапе, `R` — очки соперника перед этапом,
`y` — его результат, а `M` — максимум соперника после этапа, то титул гарантирован
по очкам при `C + x > R + y + M`. При равенстве учитываются результаты гонок;
для сезона 2026 затем применяются результаты квалификаций. Спринты приносят очки,
но не победы для сравнения результатов основных гонок.

Максимум пилота — 25 очков в гонке и 8 в спринте; максимум команды — 43 и 15.
Командный результат складывается из двух разных мест. Проверка совместимости
исключает сценарии с одинаковыми местами у разных участников. Учитываются
оставшиеся спринты и отменённые этапы. Процент вероятности не рассчитывается.

Расчёт предполагает полное начисление очков. При сокращении дистанции, отмене
сессии или изменении календаря нужны обновлённые данные. Если таблицы не относятся
к нужному этапу либо архив неполон, сервис возвращает `unavailable`, а не
утверждение, что никто не может стать чемпионом.

Источник правил: [FIA, раздел A, A2.1.4 и A2.2](https://www.fia.com/system/files/documents/fia_2026_f1_regulations_-_section_a_general_provisions_-_iss_02_-_2026-02-27.pdf).

## API и хранение

`GET /api/predictions/championship` — публичные условия текущего этапа: статус,
кандидаты `drivers` и `constructors`, их очки, варианты набора очков, финиши и
ограничения для соперников. Ответ не содержит аккаунтов или чужих прогнозов.
После спринта используются его подтверждённые результаты.

В `POST /api/predictions/current` добавлен необязательный объект:

```json
{
  "championship": {
    "drivers": {"id": "ANT", "yes": false},
    "constructors": {"id": "mercedes", "yes": true}
  }
}
```

Это дополнение к обычным полям прогноза. Сервер заново проверяет доступность
кандидата. Для единственного кандидата `id` можно опустить. Недоступный вид зачёта
не передаётся. `null` сохраняет совместимость со старыми клиентами.

Миграция 3 добавляет nullable-поля `championship_json` и
`championship_context_json`. Сохраняются ответ, имя и исходные данные расчёта;
полные перечни финишей для каждого пользователя не дублируются. В личном разборе
результат проверяется по подтверждённым таблицам конкретного этапа; при задержке
данных показывается ожидание, а не неверный ответ «Нет».

В Telegram помещается короткий пример под спойлером. Все варианты доступны в
раскрывающемся блоке формы. Спойлер Telegram скрывает содержание, но не уменьшает
длину сообщения.

## Проверка и предпросмотр

React-компонент находится в `ChampionshipForecast.tsx`, общие типы и проверка
заполненности ответов — в `championship.ts`. Это сохраняет совместимость с
правилом Fast Refresh: модуль компонента экспортирует только компонент.

```powershell
npm.cmd --prefix front run lint -- --ignore-pattern "public/race-game/**"
npm.cmd --prefix front test
```

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_championship.py -q
.\.venv\Scripts\python.exe scripts/build-championship-preview.py
node scripts/check-championship-ui.cjs
```

Проверка интерфейса использует локальный Vite на `127.0.0.1:5176`. Данные в
`artifacts/championship` демонстрационные и рассчитаны тем же модулем, что API.
Скриншоты показывают настоящую React-форму.

Проверка HTTP-загрузки архива использует существующий локальный Postman-симулятор:

```powershell
postman simulation run postman/simulations/forecast-recovery.sim.yaml --port 4902 --output ndjson
.\.venv\Scripts\python.exe scripts/check-championship-simulation.py
```

Проверяются недоступность источника и восстановление загрузки результатов гонок
и квалификаций. Календарь и таблицы для этой проверки синтетические; проверка не
подтверждает доступность боевых источников.
