# Тест-дизайн и запуск проверок

## Область проверки

Инвентаризация охватывает серверные файлы `tests/test_*.py`, фронтенд
`front/tests/*.test.mjs` и `*.test.ts`, навигацию `tests/navigation.test.mjs`,
игру `race-game/tests/*.test.mjs` и контракт выката `deploy/jenkins/test_deploy.py`.
`python scripts/test-inventory.py` показывает все определения без импорта приложения.
Число определений отличается от числа сценариев после параметризации.

Существующие содержательные регрессионные проверки сохранены. Переработаны
общая изоляция, запуск и слабые сценарии; независимые входные данные вынесены
в именованные случаи. Последовательности, проверяющие повторную отправку,
миграцию или восстановление, остаются последовательностями действий.

## Техники и ожидаемые результаты

- **Авторизация и аккаунты.** Классы допустимого и ошибочного email; границы
  64/65 символов локальной части, 254/255 общей длины, 11/12 символов и
  72/73 UTF-8 байт пароля. Проверки до, в момент и после истечения кода.
  Переходы активной сессии после выхода, архивации, истечения и подмены токена.
  Сохранены сценарии CSRF, ролей, объединения аккаунтов и удаления данных
  в `test_account_auth`, `test_auth_api`, `test_admin_api` и `test_admin_tools`.
- **Прогнозы.** Таблицы решения для точного места, отклонений на 1/2/3 позиции
  и отсутствующего результата. Ожидаемые баллы заданы правилами; ожидаемый
  результат не вычисляется другим вызовом того же механизма начисления.
  Отдельно проверяются нулевой safety car, неизвестные факты и спринтовые поля.
  Сохранены сценарии истории, объяснений, закрытия, восстановления, аналитики
  и источников гонки. Время окна закрытия фиксировано, проверяется его конец.
- **Уведомления.** Все 32 комбинации интервалов и категорий сессий,
  совместимость старого значения, пустая настройка и неправильные типы.
  Переходы очереди из конечных состояний не создают повторных сообщений;
  срок доставки проверяется до, на и после границы. Для недельного обгона
  проверяются ничья, возврат рекорда, приватность, архивация, удаление заезда,
  конец недели и граница часового ограничения. Сохранены проверки звука,
  rich-message транспорта, групп, ссылок, недельных итогов и персональных входящих.
- **API и данные F1.** Ошибочный ввод, недоступность, частичные протоколы,
  источник официальных очков, порядок и отсутствие побочных действий.
  В сравнении тестовые итоговые очки намеренно отличаются от суммы гонок:
  это проверяет сохранение спринтов и корректировок. Расписание, зачёт и
  факты гонки подменены на явных границах, без обращения к накопленному кэшу.
  Сохранены контракты календаря, сезонных данных, прогноза модели и recap.
- **Аналитика.** Невалидные и частичные метрики не становятся нулями.
  Проверяются границы cutoff, повтор снимка, независимость версий и среднее
  разных этапов. Для приватных маршрутов и произвольного текста проверяются
  точный HTTP-статус и отсутствие записанной аналитики.
- **Фронтенд.** Момент начала и конца сессии, дедлайн и порог срочности
  прогноза, дневной горизонт напоминания, приоритет одновременных событий,
  месячная пауза и лимит подсказки установки. Сохранены проверки состояния
  sharing, доступности селекторов, навигации, карт, словаря и таймеров.
  Общий загрузчик исполняет реальные TS-модули, подменяя только зависимости.
- **Гонка.** Нулевые, отрицательные и нечисловые кадры; сохранение времени
  движения и граница ограничения после паузы; границы полосы финиша,
  направление пересечения и интерполяция. Сохранены проверки столкновений,
  привязки рекорда к трассе, ghost и полноты серверной телеметрии.
- **Почта и выкат.** Выбор транспорта, парность SMTP-учётных данных,
  порядок TLS/авторизации/отправки и отказ транспорта. Шесть сценариев
  выката используют подставной Docker: успех, отказ резервной копии,
  неуспешный запуск, health-check, откат и неизменившийся образ.

Проверки исходного CSS/архитектуры и происхождения ресурсов остаются
контрактами. Они не считаются доказательством работы интерфейса в браузере.
Существующие браузерные сценарии `scripts/check-*-ui.cjs` используют локальные
серверы и подготовленные API-ответы; запускаются отдельно для изменений интерфейса.

## Изоляция и диагностика

Конфигурация тестов задаётся до импорта приложения. Каждый серверный сценарий
получает отдельный путь SQLite и кэш F1; API-фикстура возвращает исходные
переопределения зависимостей даже при ошибке. Фикстуры не требуют `.env`
с реальным администратором. Общие фабрики находятся в `tests/support.py`;
тестовые модули не импортируются ради получения генератора данных.

По умолчанию внешние HTTP- и socket-подключения запрещены. Попытка, которую
приложение перехватило как ошибку источника, всё равно приводит к ошибке
теста при очистке. Локальные сокеты разрешены для event loop и локальных
сервисов; штатные HTTP-проверки используют ASGITransport.
Утилита настоящей отправки писем находится отдельно в `scripts/smoke_email.py`
и не вызывается автоматическим набором.

Маркеры `unit` и `integration` определяются по используемым фикстурам,
`live` выделяет внешние API. Строгая проверка маркеров исключает опечатки.
`--case-notes` включает описания сценариев. `--test-order-seed` воспроизводит
перемешивание и помогает обнаруживать зависимость от порядка.

## Запуск

После установки `requirements.txt` и зависимостей обоих npm-проектов,
из активного Python-окружения:

```text
python scripts/run-test-suite.py --coverage
python scripts/run-test-suite.py --seed 42
python scripts/run-test-suite.py --list
```

Нужен Node с поддержкой `--experimental-strip-types` (в CI используется Node 22).
Для контракта выката нужен sh либо Windows Git Bash; отсутствие оболочки
явно отображается как пропуск. Единый запуск прекращается при ошибке любого набора.

Отдельные команды:

```text
python -m pytest -q
python -m pytest -m integration --test-order-seed=42
python -m pytest --cov=app --cov-branch --cov-report=xml:artifacts/coverage.xml
npm --prefix front test
npm --prefix race-game test
npm --prefix front run test:mutations
python deploy/jenkins/test_deploy.py
```

Проверки реальных API выполняются только явной командой
`python -m pytest tests/test_prediction_api_sources_live.py --live`.
Они читают источники и не являются частью автоматического offline-прогона.

## Подтверждение качества и ограничения

Восемь выбранных мутаций заменяют операторы границ и пределы времени только
в памяти дочернего процесса. Сначала должны пройти оригинальные тесты,
затем каждая мутация должна вызвать AssertionError. Ошибка загрузки или
таймаут не считается обнаруженной мутацией. Это проверка чувствительности
выбранных границ, а не полный mutation score всего проекта.

JUnit, логи и покрытие сохраняются в `artifacts/`; в CI — в `reports/`.
Покрытие строк и ветвей измеряется отдельно. Число тестов и процент покрытия
не заменяют проверку правильного результата, отрицательных сценариев и
побочных действий. Общий порог покрытия не добавлен без исходного требования.

Проверка 5 октября 2026 года: 1258 серверных сценариев прошли, два live-сценария
пропущены; 117 frontend, 40 игровых и шесть deployment-сценариев прошли.
Весь набор успешно проверен с двумя порядками серверных тестов: seed
20261005 и 42. Все восемь выбранных мутаций обнаружены. Последний отчёт
покрытия сервера: 66,85% строк и 54,10% ветвей. Эти метрики относятся к
текущему набору и не означают полного покрытия бизнес-сценариев.
