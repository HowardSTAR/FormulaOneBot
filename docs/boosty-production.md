# Подписки Boosty в production

Проверка доступна всем пользователям с подтверждённым email, совпадающим с email
на Boosty. Telegram не обязателен. `BOOSTY_PILOT_TELEGRAM_IDS` больше не ограничивает
проверку. Фоновая синхронизация выполняется каждые 5 минут; кнопка проверки
использует тот же сервис с ограничением частоты до одного запроса в минуту.
Отмена автопродления сохраняет оплаченные преимущества до `offTime`;
при включённом продлении срок берётся из `nextPayTime`. Если указаны обе даты,
используется ближайшая. Активный платный уровень определяется по `status=active`
и положительной цене; `isFeePaid` не используется как признак оплаты, поскольку
в реальном ответе Boosty он бывает `false` у действующей оплаченной подписки.

## Подключение владельца

### Вход без копирования токенов

На компьютере владельца один раз установите необязательные зависимости:

```powershell
.venv/Scripts/python.exe -m pip install -r requirements-boosty-connect.txt
```

Затем запустите `connect-boosty.cmd` двойным щелчком. Откроется отдельное окно
Microsoft Edge: войдите в аккаунт владельца Boosty обычным способом. Утилита
получит только `auth` и `_clientId` для `boosty.to`, закроет отдельный браузер
без выхода из аккаунта, проверит доступ к подписчикам и передаст сеанс по SSH.
Ваш основной браузер и его cookies не используются. Пароли и коды входа
вводятся только на странице Boosty, а значения токенов не печатаются.

Для удалённого сервера настройки находятся в исключённом из Git файле
`secrets/boosty-connect.json`:

```json
{
  "host": "your-server.example",
  "username": "root",
  "container": "formulaonebot-web-1",
  "key_file": "C:/Users/owner/.ssh/id_ed25519"
}
```

Вместо `key_file` можно задать `password_file` — путь к локальному файлу пароля.
Ключ сервера должен уже быть доверенным в SSH known_hosts. Для отдельного файла
есть `known_hosts`. Неизвестный или изменившийся ключ блокирует передачу сеанса.
При неудачной передаче можно повторить `connect-boosty.cmd --retry`: свежий сеанс
временно сохраняется в `secrets/boosty-pending-auth.json` и удаляется после успеха.
Если токен уже отклонён Boosty, нужен новый вход.

Без SSH-конфигурации утилита устанавливает подключение в локальный проект.
Альтернативы Edge: `--browser chrome` или `--browser chromium` (для последнего
сначала выполните `python -m playwright install chromium`).

Новая авторизация устанавливается только после проверки полного списка
подписчиков и его формата. Затем сразу выполняется синхронизация прав.
Обычная смена токенов больше не требует запуска утилиты.

### Ручной импорт для обслуживания

В контейнере web задаются `BOOSTY_BLOG=turbotears` и, при необходимости,
`BOOSTY_AUTH_FILE=/app/data/boosty-auth.json` (это также путь по умолчанию).
Файл находится в постоянном томе `/root/FormulaOneBot/data`, а не внутри образа.
Он содержит `access_token`, `refresh_token`, `device_id` и необязательный
`expires_at` — Unix-время в секундах. Доступ к файлу ограничивается владельцем.

Для первоначального подключения в браузере владельца нужны cookie `auth`
и `_clientId`. Сохраните их локально в исключённый из Git файл
`secrets/boosty-browser-session.json`:

```json
{"auth":"значение cookie auth","device_id":"значение cookie _clientId"}
```

Импорт принимает URL-кодированный `auth`, обычный JSON из cookie или уже
нормализованный объект. Значения не передаются в аргументах команд и не выводятся:

```sh
python scripts/configure_boosty_auth.py --input secrets/boosty-browser-session.json --output data/boosty-auth.json
```

Переносите итоговый файл на сервер по SSH/SFTP. Не отправляйте его в Git,
Jenkins-артефакты или чат. Старый `BOOSTY_ACCESS_TOKEN` и файл
`BOOSTY_ACCESS_TOKEN_FILE` поддерживаются как резервный источник, но не умеют
продлевать авторизацию. Сохранённый JSON имеет приоритет над старым токеном.

Перед истечением токена и после HTTP 401 сервис обновляет авторизацию один раз,
атомарно сохраняет новую пару токенов и повторяет запрос. Ошибки сети,
авторизации и неполные ответы не отменяют ранее подтверждённую подписку;
её оплаченный срок продолжает учитываться. Отозванный refresh token требует
повторного подключения владельцем.

Обновление защищено файловой блокировкой: разные процессы и экземпляры сервиса
не обновляют одну пару одновременно. Новый сеанс подхватывается фоновым сервисом
в течение 15 секунд без перезапуска web. При кратком сбое сети фоновая проверка
повторяется через минуту.

### Выдача и снятие прав

Сопоставление выполняется по одинаковому подтверждённому email. Оплаченный
активный уровень выдаёт соответствующие права; очередная проверка продления
обновляет срок и сохраняет доступ. Переход на другой уровень меняет права
согласно новому уровню, сохраняя ранее выбранное оформление.

После сохранённого оплаченного срока доступ прекращается на сервере даже без
нового запроса к Boosty. Отмена автопродления сохраняет доступ до конца оплаты.
Сетевой сбой не считается окончанием подписки; подтверждённый срок продолжает
действовать, но не продлевается предположительно. Если Boosty не передал срок,
окончание определяется следующей успешной синхронизацией.

Ручной премиум главного администратора имеет приоритет над подпиской и не
отключается по её окончании. Для проверки автоматического режима выберите
«По подписке Boosty» в настройках своего премиума. Обычные участники работают
по подписке без ручного назначения прав.

## Устойчивая авторизация

Смена access token сама по себе не требует ручного вмешательства: сервис сохраняет
обновлённые access/refresh tokens в постоянном томе. Для подключения используйте
отдельный профиль браузера и отдельный вход владельца, предназначенный для
интеграции. После импорта не используйте этот же сеанс для обычной работы:
браузер тоже обновляет токены, и сохранённая сервером пара может устареть.
Это снижает риск конкуренции с браузером, но не защищает от отзыва сеанса Boosty.

При HTTP 401 выполняется одно обновление авторизации. Если Boosty отклоняет его
(например, `invalid_grant`), текущего refresh token недостаточно для восстановления:
нужен новый вход владельца. API статуса отдаёт `check_error_code=auth_required`,
а кабинет и редактор профиля показывают необходимость восстановления подключения.
Повторная проверка не снимает ранее подтверждённые оплаченные преимущества.

Временные ошибки чтения списка подписчиков повторяются до трёх попыток с короткой
паузой. Длительный `Retry-After` не обходится. Запрос обновления токенов не
повторяется вслепую: потерянный ответ мог содержать уже сменившуюся пару токенов.

## Проверка релиза

Дождитесь успешных проверок и deployment в Jenkins. Затем убедитесь, что Boosty
возвращает полный список подписчиков и синхронизация обновила `checked_at`.
Для проверки проблемного аккаунта сопоставьте подтверждённый email, оплаченный
уровень и срок. Не подменяйте ошибку авторизации пустым списком и не выдавайте
премиум всем пользователям при сбое Boosty.
