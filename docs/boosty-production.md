# Подписки Boosty в production

Проверка доступна всем пользователям с подтверждённым email, совпадающим с email
на Boosty. Telegram не обязателен. `BOOSTY_PILOT_TELEGRAM_IDS` больше не ограничивает
проверку. Фоновая синхронизация выполняется каждые 15 минут; кнопка проверки
использует тот же сервис с ограничением частоты до одного запроса в минуту.
Отмена автопродления сохраняет оплаченные преимущества до `offTime`;
при включённом продлении срок берётся из `nextPayTime`. Если указаны обе даты,
используется ближайшая. Активный платный уровень определяется по `status=active`
и положительной цене; `isFeePaid` не используется как признак оплаты, поскольку
в реальном ответе Boosty он бывает `false` у действующей оплаченной подписки.

## Подключение владельца

В контейнере web задаются `BOOSTY_BLOG=turbotears` и, при необходимости,
`BOOSTY_AUTH_FILE=/app/data/boosty-auth.json` (это также путь по умолчанию).
Файл находится в постоянном томе `/root/FormulaOneBot/data`, а не внутри образа.
Он содержит `access_token`, `refresh_token`, `device_id` и необязательный
`expires_at` — Unix-время в секундах. Доступ к файлу ограничивается владельцем.

Для первоначального подключения в браузере владельца нужны cookie `auth`
и `_clientId`. Сохраните их локально в исключённый из Git файл
`secrets/boosty-browser-session.json`:

```json
{"auth":"значение cookie auth","device_id":"значение cookie _clientId"}
```

Импорт принимает URL-кодированный `auth`, обычный JSON из cookie или уже
нормализованный объект. Значения не передаются в аргументах команд и не выводятся:

```sh
python scripts/configure_boosty_auth.py --input secrets/boosty-browser-session.json --output data/boosty-auth.json
```

Переносите итоговый файл на сервер по SSH/SFTP. Не отправляйте его в Git,
Jenkins-артефакты или чат. Старый `BOOSTY_ACCESS_TOKEN` и файл
`BOOSTY_ACCESS_TOKEN_FILE` поддерживаются как резервный источник, но не умеют
продлевать авторизацию. Сохранённый JSON имеет приоритет над старым токеном.

Перед истечением токена и после HTTP 401 сервис обновляет авторизацию один раз,
атомарно сохраняет новую пару токенов и повторяет запрос. Ошибки сети,
авторизации и неполные ответы не отменяют ранее подтверждённую подписку;
её оплаченный срок продолжает учитываться. Отозванный refresh token требует
повторного подключения владельцем.

## Проверка релиза

Дождитесь успешных проверок и deployment в Jenkins. Затем убедитесь, что Boosty
возвращает полный список подписчиков и синхронизация обновила `checked_at`.
Для проверки проблемного аккаунта сопоставьте подтверждённый email, оплаченный
уровень и срок. Не подменяйте ошибку авторизации пустым списком и не выдавайте
премиум всем пользователям при сбое Boosty.
