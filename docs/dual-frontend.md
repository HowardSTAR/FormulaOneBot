# Две оболочки перед релизом

Production-сборка содержит два независимых интерфейса:

- `f1hub.ru` и `www.f1hub.ru` → `web` → `front/legacy-dist`, точный архив production-сборки
  `34704c571ac2`, сохранённый 1 ноября 2026 года в `legacy/`.
- `new.f1hub.ru` → `web-new` → `front/dist`, актуальный редизайн из `front/`.

Оба web-процесса используют одну БД, Redis и одинаковый API. Изменения прогнозов,
профиля и административные действия на новом домене меняют настоящие данные.
Это предпросмотр оболочки, а не изолированная тестовая база. Bot и worker
остаются в единственном экземпляре. Вход выполняется отдельно на каждом домене
(сессионные cookies не имеют общего Domain). Новый домен получает noindex.

## Перед слиянием и первым production-запуском

1. Проверить контрольные суммы сохранённого интерфейса по `legacy/release.json`.
   Архив снят непосредственно с работающего сайта, включая игру и картинки.
2. Создать DNS-запись `new.f1hub.ru` на тот же сервер, что `f1hub.ru`.
3. Выпустить отдельный сертификат `new.f1hub.ru` через существующий webroot
   `ssl/acme`. Скопировать его в `ssl/new/fullchain.pem` и `ssl/new/privkey.pem`.
   Добавить соответствующую ветку в renewal deploy hook. Сертификат основного
   домена продолжает использовать прежние пути.
4. Если WEB_ORIGINS задан в серверном `.env`, добавить туда
   `https://new.f1hub.ru`. PUBLIC_WEB_URL основного сервиса оставить прежним.
   Настройки разрешённых доменов внешнего входа также проверить для поддомена.
5. Обновить серверный `docker-compose-build.yml` и `nginx.conf`, а также
   доверенный `/opt/f1hub-ci/deploy-verified.sh` из этой ветки. Jenkins берёт
   эти файлы с сервера, а не автоматически из checkout. Не перечитывать Nginx
   до запуска `web-new`: его имя должно разрешаться в сети Compose.
6. После проверки сборки слить ветку в main. Развёртывание должно запускать
   `bot web web-new worker`; Nginx перечитывается после готовности обоих web.
   Для первого включения обновить также зависимости Nginx через Compose.
7. Проверить `/health`, главную, прямой переход на внутреннюю страницу,
   загрузку `/static/`, вход и выход на обоих доменах. На основном домене
   должен остаться старый дизайн, на новом — новый. Проверить Telegram Mini App.

Ветка сама не меняет DNS, сертификат или файлы в `/opt/f1hub-ci`.
Не отправлять её в main до подготовки сервера: main автоматически развёртывается.

## Разработка

`npm run dev` в `front` по-прежнему запускает новый интерфейс. В Docker
`FRONTEND_VARIANT=legacy` выбирает сохранённую сборку (по умолчанию),
`FRONTEND_VARIANT=new` — новый дизайн. Без сохранённой сборки локальный Python
использует обычный `front/dist`.

Снимок legacy не обновляется вместе с редизайном. Общий API должен сохранять
совместимость с ним. Переход основного домена на новый дизайн — отдельный релиз.
