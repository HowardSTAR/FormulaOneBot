# Оптимизация открытия сайта

## Что изменено

- Главная загружается сразу; остальные страницы, их CSS, Chart.js и игры —
  только при переходе. Suspense находится внутри основного контента, поэтому
  меню не исчезает во время загрузки раздела. Права доступа сохранены.
- На главной монтируется одна версия разметки: desktop при ширине от 900 px,
  mobile ниже. Больше нет двух скрытых таймеров и двух личных блоков.
- Расписание получает только HeroDataProvider; повторная параллельная загрузка
  объединяется. Зачёт не загружается повторно при появлении того же сезона.
- Одновременные одинаковые GET-запросы объединяются. Готовые ответы и ошибки
  не кешируются; следующий запрос обращается к серверу заново. Запросы разных
  параметров, авторизаций и таймаутов не смешиваются. POST/PATCH/DELETE не
  объединяются. Смена пользователя сбрасывает объединение запросов.
- Секундный таймер и личные часы останавливаются в скрытой вкладке и догоняют
  текущее время при возвращении. Личные данные при возвращении обновляются
  не чаще раза в минуту; кнопка «Обновить» по-прежнему обновляет сразу.
- Схема трассы остаётся видна, но без прорисовки stroke-dasharray, лишних
  animation frames и принудительного layout. Убраны вложенный SVG-фильтр,
  большие blur-фоны и постоянный will-change у линий.
- Иконки имеют размеры и асинхронное/ленивое декодирование. Закрытые подменю
  и закрытое мобильное меню не монтируют все свои ссылки и изображения.

## Измерения

Сравнение двух production-сборок одного проекта, до и после изменений.
Размеры учитывают все статически импортируемые зависимости стартового
документа. Ленивая загрузка остальных разделов в эти размеры не входит:

- JavaScript: 960 272 → 357 215 байт (примерно −63%).
- JavaScript с gzip: 295 989 → 114 435 байт (примерно −61%).
- CSS: 401 710 → 313 957 байт (примерно −22%).
- CSS с gzip: 61 094 → 44 152 байта (примерно −28%).

На изолированном локальном сервере с тестовым аккаунтом при первом открытии:
проверка аккаунта — 3 → 1 запрос, расписание — 2 → 1,
каждый из трёх личных запросов — 2 → 1. В браузере подтверждены один Hero,
один PersonalHome, отсутствие скрытой версии главной и статичные линии
трассы с transition 0s. Проверены мобильное меню и переходы в историю и
сравнение; Chart.js запрашивается при открытии сравнения, а не главной.

Это измерение размера/повторных загрузок, не доказательство конкретного
снижения CPU или устранения всех лагов на компьютере пользователя. После
публикации стоит повторить проверку на его устройстве с записью Performance
в инструментах браузера. Скорость сети, расширения и аппаратное ускорение
этим тестом не измерялись. Продакшен, БД и реальные рассылки не менялись.

## Проверки

Из папки `front`:

```text
npm run test:performance
npm run build:front
npm run check:budget
npx tsc --noEmit -p tsconfig.app.json
npm run lint
```

Бюджет проверяет стартовый JS (менее 450 КБ и 145 КБ gzip), рекурсивно
учитывает статические imports и не разрешает перенести Chart.js, игры или
админку обратно в стартовый граф зависимостей. Manifest создаётся Vite.

Для повторяемой браузерной проверки без настоящего API/БД из корня проекта:

```text
node scripts/serve-perf-fixture.mjs front/dist 4179 --signed
```

Сервер доступен только на `127.0.0.1`. Без `--signed` проверяется гостевой
сценарий. Счётчики запросов доступны на `/__perf/report`. Данные вымышленные,
неизвестные API возвращают ошибку; это не замена полному интеграционному
тесту сервера. Для сравнения сохранённых сборок:

```text
node scripts/check-front-budget.mjs .tmp/perf-before --report-only
node scripts/check-front-budget.mjs .tmp/perf-after
```
