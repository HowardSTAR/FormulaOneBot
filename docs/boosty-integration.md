# Проверка Boosty: первый запуск

В личном кабинете `/account` добавлены статус подписки и значок поддержки
TurboTears. Проверяется блог `https://boosty.to/turbotears`.
По умолчанию пилот доступен только аккаунту с привязанным Telegram ID `2099386`.
ID Telegram не используется как ID Boosty.

## Настройка сервера

В серверное окружение (локальный `.env` или секрет окружения web-контейнера):

```dotenv
BOOSTY_BLOG=turbotears
BOOSTY_PILOT_TELEGRAM_IDS=2099386
BOOSTY_ACCESS_TOKEN=<access token владельца блога>
```

Токен берётся из авторизованного аккаунта **владельца блога** Boosty.
Хранить его только на сервере, не в чате, Git или переменных `VITE_*`.
Нужен именно токен доступа, без префикса `Bearer`. После истечения токена
его потребуется заменить и перезапустить backend. Автообновление токена
в этом первом варианте не реализовано.

Для локального запуска вместо `.env` можно сохранить только значение токена
в `secrets/boosty-access-token.txt` (UTF-8). Этот каталог уже исключён из Git.
Backend автоматически читает этот файл, если `BOOSTY_ACCESS_TOKEN` не задан.
Для другого пути предусмотрен `BOOSTY_ACCESS_TOKEN_FILE`. В контейнере файл
нужно отдельно смонтировать как секрет либо использовать переменную окружения.

Нужно развернуть изменённый backend и собранный frontend.
Без токена кабинет показывает «Подключение проверки готовится».
Рабочая БД и production-окружение при разработке не изменяются.

## Сопоставление и проверка

Сопоставляется подтверждённый email сайта с email из списка подписчиков
владельца Boosty. Если адреса разные, подписка не найдётся. Ввод чужого
Boosty ID или неподтверждённого email не выдаёт значок.

Backend проверяет подписки при запуске и каждые 15 минут. Кнопка в кабинете
позволяет проверить раньше; обращения к Boosty ограничены одним в минуту
на процесс, включая неудачные попытки. Кабинет обновляет отображение раз в минуту.

Уровень подписки и активность хранятся отдельно от ролей администратора,
обычных настроек и Telegram-профиля. При завершении подписки снимается только
значок поддержки. Ограничение платных функций пока не добавлено.

Полный список загружается постранично. Ошибки авторизации, сети, изменения
формата ответа, повторяющиеся записи или неполные страницы сохраняют
последний подтверждённый статус. Удаление аккаунта удаляет и запись Boosty.

## Ограничения первой версии

Используется внутренний API, не гарантированный официальный контракт:
https://github.com/an1by/boosty-js/blob/main/src/api-client/subscribers.ts
https://github.com/an1by/boosty-js/blob/main/src/model/subscribers.ts

Признаки платного доступа: `price > 0`, `isFeePaid`, отсутствие блокировки,
будущий `nextPayTime` (Unix seconds), а при отсутствии даты — `subscribed`. До production-пилота
нужно подтвердить значения этих полей на реальном ответе владельца блога,
особенно после отключения автопродления и завершения оплаченного периода.
При несовместимом формате синхронизация прекращается без снятия значков.
Живое получение подписчиков не проверено без авторизации владельца.

Email является доказательством владения почтой, а не полноценной авторизацией
Boosty. Перед открытием интеграции всем пользователям отдельно согласовать
способ подтверждения аккаунта и проверить поведение всех уровней подписки.
