# Приоритеты ошибок бота

В текущем middleware обработки Telegram updates больше нет одинакового `BOT CRITICAL ERROR`
для любого исключения. Применяется классификация:

- **Минимальный**: устаревший callback или сообщение без изменений.
- **Низкий**: сетевой сбой/тайм-аут, FloodWait, пользователь заблокировал бота.
- **Средний**: прочие ошибки обработки команды. Пятая и последующие повторные низкоприоритетные
  ошибки в серии также получают средний приоритет. Это признак повторяемости, не доказательство полного отказа.
- **Критический**: ошибка работы SQLite, например отсутствующая таблица или блокировка БД.
- **Блокирующий**: недействительный токен Telegram, конфликт polling, повреждение/недоступность
  БД, заполненный/read-only диск, MemoryError.

`report_error(error, bot=bot, source="bot.update", priority=None)` также позволяет явно назначить
уровень в других контролируемых местах приложения. Обычные записи logger автоматически не перехватываются;
ошибки до запуска middleware, перезапуски контейнера и завершение процесса ОС требуют внешнего мониторинга.

## Доставка и безопасность

- В Telegram — существующему `ADMIN_TELEGRAM_ID` (или совместимому `ADMIN_IDA`).
- На сайт → «Уведомления» — всем активным admin/superadmin, даже до первого посещения страницы.
- Push — только на ранее подписанные устройства, при настроенных VAPID-ключах.
- При снятии роли администратора алёрты скрываются из inbox и не отправляются из очереди push.
  Уже доставленные на устройство уведомления отозвать нельзя.
- На сайт и Telegram уходит краткая сводка с уровнем, типом, источником, местом и счётчиком.
  URL, Telegram-токены, Bearer-токены, email и типовые поля секретов маскируются; полный traceback
  остаётся в серверном логе. Не добавляйте секреты и персональные payload в тексты исключений.

## Повторы и сбои

Одинаковые источник/тип/место/исходный уровень группируются в SQLite `admin_error_incidents`.
Повторы обновляют счётчик в уже существующем уведомлении. Новая отправка — не чаще 15 минут
(минимальный: раз в час) либо при изменении уровня. Счётчик серии сбрасывается после 15 минут тишины.
Повышение уровня создаёт отдельное уведомление. Дедупликация переживает перезапуск.

Исторические логи не читаются и не рассылаются при запуске. Правило пропуска старых push
при рестарте сохранено. При недоступном Telegram сайт сохраняет алёрт независимо;
при недоступной БД есть ограниченный по частоте Telegram fallback в памяти процесса.
Ошибки доставки не вызывают рекурсивных алёртов; Telegram автоматически не переотправляется
из отдельной очереди. При полном отказе БД сохранение уведомления на сайт невозможно.

Новых переменных окружения не требуется. Обновить frontend, перезапустить bot и web;
таблицы создаются автоматически при первой записи. БД должна быть общей для bot и web.
